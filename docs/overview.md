# Overview

**MT Macro** is an offline-first personal tracker for **food, sleep, body-weight trend and daily habits**, built for one user on a muscle-gain (bulking) diet. The full product brief is [`../blueprint.md`](../blueprint.md).

## Who it is for

- 20-year-old student in Iraq, ~167 cm / ~56 kg, bulking towards ~3,000 kcal/day.
- Mid-range Android phone, low budget, prefers everything local and free.
- Types food names in **Arabic (Iraqi dialect) or English**; UI is English.
- Already uses the **Hadeedi** app for workouts. This app must **not** track workouts.

## Scope

| In scope | Out of scope |
|---|---|
| Food log (3 static meals as templates + 2 home-cooked "mom's" meals) | Workout tracking (Hadeedi does it) |
| Macro/calorie progress vs targets | Medical advice (informational only) |
| Sleep log + 7-day stats | Cloud accounts, sync, paid services |
| Body weight + 7-day average + calorie adjustment rule | |
| Habits: creatine, water | |
| "Something went wrong" recovery advice | |
| JSON backup/restore | |
| Offline food database + on-device AI estimates (Byte) | Cloud AI (the model runs on the phone) |

## Current phase

Phase 1 MVP + Phase 2 polish are built, and the first Phase 3 pieces: a bundled **USDA food database** ([food-database.md](food-database.md)) and **Byte**, an on-device AI chat that turns "what I ate" into a database-computed entry ([ai.md](ai.md)). Static meals are editable templates; dynamic (mom's) meals go through Byte. The AI model is downloaded inside the app, not shipped with it. See [roadmap.md](roadmap.md).

## Core principle (applies to every future AI feature)

> The model may parse and reason; **numbers must come from a food database and deterministic code**, never generated by an LLM.

All calculations live in deterministic code (`app/src/logic.ts`, `foodDb.ts`) — see [logic.md](logic.md). Byte follows the principle: the model only names foods and amounts; grams and macros come from the database ([ai.md](ai.md)).
