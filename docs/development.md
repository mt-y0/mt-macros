# Development

All commands run inside `app/` — or use the root **`Makefile`** (`make help`):

| `make …` | Does |
|---|---|
| `dev` / `build` / `lint` / `check` / `preview` | npm scripts (check = build + lint) |
| `apk` | build + `cap sync` + Gradle debug APK → `app/mt-macro-<versionName>.apk` |
| `install-apk` / `run` | install (and launch) on a USB phone via adb |
| `logcat` / `devices` | phone console logs / list phones (UI inspector: `chrome://inspect`) |
| `clean` | remove `dist/`, Android build, APKs |

The Makefile sets `JAVA_HOME` / `ANDROID_HOME` itself.

## Commands

| Task | Command |
|---|---|
| Install | `npm install` |
| Dev server (also on LAN for the phone) | `npm run dev -- --host` → `http://localhost:5173/`, phone: the printed Network URL (same Wi-Fi) |
| Type-check + production build | `npm run build` → `dist/` |
| Preview the build (PWA/offline behaves like production) | `npm run preview -- --host` |
| Lint | `npm run lint` |
| Regenerate food icons (SVG) | `node scripts/food-icons.mjs` |
| Rebuild the food database | `node scripts/food-db.mjs` (downloads USDA CSVs once into `.cache/usda/`; needs `curl`, `unzip`) |
| Regenerate logo + icons (web + Android) | `node scripts/logo.mjs` (needs `rsvg-convert` and ImageMagick `magick`) |
| Screenshot (phone size) | `node scripts/screenshot.mjs <url> <out.png> [light\|dark] [Food\|Byte\|Days\|Weight\|Sleep\|Meals\|Settings\|LOG\|SPLASH\|DROP] ['{prefs json}']` |

The screenshot script needs `chromium` on PATH and the dev server running; it opens a **visible** window (see [Testing](#testing)) with a fresh temporary browser profile each run (empty database, seeded on load). `LOG` taps the first three usual meals before capturing. Normal captures wait ~3.3 s so the intro splash is gone; The optional last argument is merged into the device prefs before capture, e.g. `'{"theme":"dark","accent":"orange","splash":false}'` to check a forced theme/accent. `SPLASH` captures the logo screen and `DROP` the columns mid-fall (timing depends on page-load speed).

## Testing

**Rule (from the user): tests run in a visible browser, not headless** — the user wants to see what's happening and what is being tested. Before launching, say in one line what the window will do.

- `node scripts/screenshot.mjs …` — opens a visible phone-sized Chromium window, captures, closes.
- `node scripts/drive.mjs <url> <profileDir> <outPrefix> <step…>` — scripted end-to-end run in a visible window via the DevTools protocol. Steps: `js:<expr>` (run in the page), `wait:<ms>`, `until:<expr>:<timeoutMs>` (poll until truthy), `shot:<name>`. Console output and page exceptions are printed. Reuse the same `profileDir` to keep a downloaded AI model between runs (the first download is ~500 MB).
- Example — ask Byte something and capture the answer:
  ```sh
  node scripts/drive.mjs http://localhost:5173/ ~/.cache/mt-test-profile /tmp/byte \
    "js:[...document.querySelectorAll('.tabs button')].find(b=>b.textContent.includes('Byte')).click(); 1" \
    "until:document.body.innerText.includes('on this phone') && 1:240000" "shot:ready"
  ```
- `HEADLESS=1` hides the window — only for runs nobody can watch (CI).
- Deterministic logic (`logic.ts`, `foodDb.ts`, `ai/estimate.ts`) can be checked with plain Node scripts; no browser needed.

## Android APK

Capacitor wraps `dist/` into `app/android/`. Toolchain (installed locally, not via pacman): **JDK 21** at `~/.local/share/mise/installs/java/temurin-21.0.12+101.0.LTS` (Gradle/AGP don't run on the system JDK 26) and the **Android SDK** at `~/Android/Sdk` (cmdline-tools, platform-tools, build-tools 35; Gradle fetches platform 36 itself).

```sh
export JAVA_HOME=~/.local/share/mise/installs/java/temurin-21.0.12+101.0.LTS ANDROID_HOME=~/Android/Sdk
npm run build && npx cap sync android
cd android && ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk   (or just: make apk)
```

- Version: `versionName` / `versionCode` in `android/app/build.gradle` (currently `0.0.5-pre` / 5). Bump `versionCode` for every APK you want to install over an older one.
- It's a **debug-signed** test build (fine for sideloading; not for the Play Store).
- Launcher icons (`res/mipmap-*`) and pre-Android-12 splash images (`res/drawable*/splash.png`) are generated by `node scripts/logo.mjs` from the logo — never edit them by hand. Adaptive icon: the tile shrunk to 64 dp inside the 108 dp foreground on `#2F7D74`.
- Fullscreen/immersive setup lives in `MainActivity.java` + `capacitor.config.ts` — see [architecture.md](architecture.md#android-fullscreen). `npx cap sync` does not overwrite `MainActivity.java` or `res/`.

## Definition of done for any change

1. `npm run build` passes (it runs `tsc -b`).
2. `npm run lint` has no new warnings (known: `react(purity)` on `new Date()` in event handlers in `Today.tsx` and `Chat.tsx`, and one `only-export-components` in `art.tsx` for `TabIcons` — both harmless).
3. UI changes: screenshot light + dark at phone width and look at them.
4. **Docs updated** — the relevant `docs/*.md` file, a line in [changelog.md](changelog.md), and the index in `AGENTS.md` if a doc file was added, renamed or removed.

## Conventions

- TypeScript strict-ish (`noUnusedLocals`, `verbatimModuleSyntax` → use `import type`).
- Rules and numbers go in `logic.ts` (pure); pages only wire UI to DB + logic.
- Read data with `useLiveQuery`; never cache DB rows in component state except form drafts.
- Colors only via CSS variables from `index.css`; illustrations only via variables too.
- UI copy: sentence case, plain verbs, button says what it does ("Save weight", "Log v2").
- No network calls at runtime. Anything bundled must be matched by the Workbox `globPatterns` in `vite.config.ts`.

## Gotchas

- **wllama types:** the package ships raw `.ts` sources beside its build, so `tsconfig.app.json` maps `@wllama/wllama` to `esm/index.d.ts` (`paths`). Don't remove it — `tsc` would type-check wllama's sources and fail.
- **Testing Byte for real:** the dev server sends COOP/COEP headers, so `scripts/drive.mjs` with a persistent profile dir can download a model once through Settings and then chat (`crossOriginIsolated` is `true`). The deterministic half (`ai/estimate.ts`, `foodDb.ts`) needs no model.
- **Sound in the browser** stays silent until the first tap (autoplay policy; `unlockAudio()` resumes it). The Capacitor WebView allows it, so the intro jingle plays on the phone. In dev, StrictMode plays the intro twice.
- **React StrictMode** runs effects twice in dev — any startup write must be idempotent and inside a Dexie transaction (see `seedIfEmpty`).
- Dexie 4 `EntityTable.add()` is typed `number | undefined`; use `(await table.add(x))!` when you need the id.
- Data is per browser: phone and PC have separate databases. Use Settings → Export/Import JSON to move data.
- Changing the Dexie schema: follow the checklist in [data-model.md](data-model.md#changing-the-schema).
